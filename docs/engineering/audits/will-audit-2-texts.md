## Item 1 summary: missing keys per language, and what the code does

- Follow-ups (C-1): es, fr, it, pt have none. Pre-payment: silent skip. Paid flows: task. Approved template path logs English body (language-30oct.ts:233).
- Post-payment refund and signature messages (C-2): es, fr, it, pt get English Library rows.
- Price and objection texts (C-5, C-6, C-7): es, fr, it, pt have none; model writes the reply, guard-checked. Exception: instant path sends English (L-1).
- Handoff rows (C-8): English only, proposed with operator note; never auto-sent.
- Expenses (C-9): de and ja texts exist but are not seeded; the model uses them via the playbook.
- zh and vi (SVT only): many keys missing; the model answers through the guard (C-15). WHT zh and vi customers get no fixed text at all. Payment-proof default is English (C-10).
